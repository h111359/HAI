## Proposed resolution and inventory

Flatten source into roles/<name>/ROLE.md, independently adapt installed .hai_env/roles snapshots, and keep skills/crete-design-package byte-identical. Each source role contributes one coherent task capability: backlog-management, requirements-analysis, git-operations, quality-verification, release-management, role-authoring, software-implementation, solution-design, specification-management, workflow-authoring. Move reusable procedures/conventions/scripts/concepts to that skill; retain responsibility/scope/decision/handoff rules in ROLE.md. A shared execution-verification skill is unnecessary if quality-verification is referenced by both software-developer and quality-assurance (QA independence remains role conduct). Installed-only hai-framework-advisor gets local framework-advice skill under installed skills only. Installed role-definition-manager divergence is extracted independently, never overwritten with source.

Skills use native SKILL.md name/description frontmatter, ordinary free-form body and optional standard metadata; no mandatory role headings, model metadata, config contract or empty settings. Roles declare optional metadata hai-skills as a comma-separated ordered set of canonical skill names; this avoids custom YAML sequences in the existing safe parser. ROLE Procedures become optional when skills carry all methods. Existing role-local procedures remain supported. All reusable resources are inventoried by old path to new skill path, and links are recomputed from actual original target identity to final source or installed targets.

Existing selected settings remain exactly once under .hai_env/config/roles/<owner>.json and nonempty owner contracts remain with roles. Skills reference owner settings through runtime configuration commands. Empty legacy role contracts are removed with preserved originals; undeclared contracts become optional. No saved config/profile/instruction changes.

## Runtime interfaces

skills validate {definition}; skills list {}; skills resolve {name}; skills install {source,name,replace?,reviewed_differences?,provenance}. Pure validation accepts contained source SKILL.md; runtime resolve accepts only .hai_env/skills/<name>/SKILL.md and returns missing dependency truthfully. Role resolve returns chosen available skill entry paths; no process invocation or authority grant. Source role validation resolves skill references in root skills; installed role validation resolves only installed skills. Runtime packages install validates dependencies before staging and must not silently install source dependencies.

Add skills migrate request with candidates map (role and skill target paths to staged candidate directories), activity_id, reviewed differences and provenance; preview captures exact differences and backup destination. Apply stages and validates every candidate, preserves source and installed originals separately in Activity history, rechecks identities, then swaps, stopping on partial states without auto-merge or auto-recovery. Live workspace migration will use the same reviewed staged plan, with exact recovery instructions. Source old container removed only after exact backup verification. Historical Activity/archive/release manifest content untouched.
