## Interfaces and increments

1. Add workflow_format 3; format 1/2 parsing and existing run reads stay unchanged. Format 3 introduces `## Locations` table (Name, Purpose, Contents); output Location uses `configured:<location>/<step>-{execution}-<filename>` with exactly one runtime-filled execution token and declared step prefix. Every output is retained attempt evidence; canonical product outputs are described by the implementation report and keep ownership. No automatic stable-name publication.
2. Format-3 inputs permit `accepted:<step>/<output>` alongside workflow/incoming references. Runtime selects the last explicitly accepted producer record for that authored step/output and records its acceptance key, producing step, execution, content hash and immutable internal path. Incoming remains exact immediate predecessor. A record's transitive required sources must still equal their currently accepted sources. Superseding an upstream output invalidates dependent design/approval/implementation/QA transitively; it is not silently rebound. Optional QA defects bind only if the latest QA result declares defects. Missing sources, modified configured source bytes or superseded lineage block preparation/completion. Initial inputs remain immutable snapshots.
3. Installation `workflow install` request: definition (source path), locations (human-chosen mapping), provenance; optional expected_installed_sha256 for explicit update. Preview with no locations returns all required location purposes/content and missing keys. Apply requires all chosen values and explicit existing-definition fingerprint on update. Validate workspace-relative portable paths, containment, links/aliases, protected overlap and default shadowing. Save separate `.hai_env/config/workflows/<name>.json`; preserve chosen values on compatible ordinary update/reuse. Never invent bases or silently convert historical formats. Definition/config partial writes are reported, never auto-repaired. Installation starts no run; missing/unsafe configuration blocks workflow start independently of core startup.
4. New runs use workflow_run_format 2 with pinned configuration. Allocate configured `<base>/<run-uuid>/<step>-<execution:03>-<filename>` output destinations and reject any preexisting conflict. Assignment supplies exact workspace-relative input/output paths, attempt execution number and internal identity. Completion checks actual configured artifacts, stages immutable internal copies under the Activity attempt, commits acceptance with external identity and internal hash/copy. Earlier accepted copies survive later attempts and archival; read/show verifies internal evidence without depending on active absolute paths. New mutations recheck external required handoffs; runtime archival inspection resolves Activity-relative copies.
5. Format-3 Results adds Gate column: `none` or `human`. Gate applies only to authored approved/accepted results. Assignment exposes a checkpoint challenge bound to run, step, execution and exact required input identities. Completion requires `human_approval` containing a recorded Activity human message ID whose text explicitly approves that challenge, received as instruction after assignment. Runtime verifies typed human/received record, exact challenge and retained record/hash. Host must record the actual received message verbatim and attest semantic approval; arbitrary approval evidence strings/agent-authored records are rejected. Host attribution is not cryptographic authentication; runtime never claims otherwise. Stale scope/design/QA sources invalidate checkpoint dependencies. Source-backed provenance may be additionally verified where actual binding is available; absent host proof is reported rather than fabricated.
6. Initial graph: prepare -> clarify -> design -> approve-design -> implement -> verify -> accept-result -> complete(backlog-manager). Authored clarification/design questions return to clarify; human change request returns to clarify; QA defects return directly to implement consuming current requirements, approved design, approval and new defects; blocked/interruption results end blocked or preserve runtime waiting; all steps have explicit cancellation/failure ending. Attempts bound by max step/run limits. QA pass is a required accepted source of final acceptance; final acceptance and QA pass are required inputs to complete. Complete instruction requires actual backlog owner authority and evidence; workflow alone grants none.
